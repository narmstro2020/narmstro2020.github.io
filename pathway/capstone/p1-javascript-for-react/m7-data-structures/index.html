    Part 1 · Module 7 — Data Structures

    7253 Software Development Capstone · self-guided · work at your own pace

    🎯 Objective

    By the end of this module you can:

    • Build a stack and say what LIFO means
    • Build a queue and say why shift() is the wrong tool at scale
    • Build a linked list and explain what a node is
    • Choose between an array, a Map, and a Set for a given job
    • Say what Big-O notation is actually trying to tell you

    🔑 Why it matters

    You will not hand-write a linked list in React. You will choose between an array and a Map almost every day.

    Both halves of this module are here on purpose. The classic structures are standards D1.8–D1.10 and they are how you learn what "fast" means. Map and Set are the ones you will reach for on Thursday.

    IdeaWhere you meet it again
    StackUndo. Browser back. The call stack your errors are printed from.
    QueueJob queues, print spoolers, React's own render queue — anything first-come-first-served
    Linked listReact's fiber tree is one. So is every structure where you insert in the middle a lot.
    Map / SetEvery day. Lookup by key, and "have I already seen this one?"

    The stretch section is where this module earns its place. You will make a queue slow, measure it, then make it fast — and Big-O will stop being a definition you memorised.

    The one idea underneath all of it

    A data structure is a promise about what is fast.

    Picking one is picking which operation you want to be cheap — and accepting that something else will be expensive. There is no structure that is best at everything, which is exactly why there is more than one.

    ⌨️ Build — structures.js

    In your capstone folder, make structures.js. Run it as you go with node structures.js.

    1 · A stack — last in, first out

    const stack = [];
stack.push("a");
stack.push("b");
console.log(stack.pop());   // "b" — the last one in
    1. Push three things, pop two, print what is left
    2. Now wrap it: write a Stack class with push, pop, peek, and a size getter
    3. Make pop on an empty stack return undefined rather than crashing — decide that deliberately

    Done when: You can say what LIFO means without expanding the letters, and your Stack hides the array completely. Nobody outside the class should be able to reach in and splice it.

    You have been using a stack all along. Print a stack trace from a thrown error and read it bottom to top — that is the call stack, and it is this exact structure.

    2 · A queue — first in, first out

    const queue = [];
queue.push("a");
queue.push("b");
console.log(queue.shift());   // "a" — the first one in
    1. Write a Queue class with enqueue, dequeue, peek, size
    2. Enqueue five, dequeue two, print what remains
    3. Read the docs for shift() and find the sentence about it being slower than pop()

    Done when: Your queue works, and you can say why shift() is not free: it re-indexes every remaining element. On five items that is nothing. Part 5 is where it stops being nothing.

    3 · A linked list — the one you build by hand

    class Node {
  constructor(value) {
    this.value = value;
    this.next = null;      // the whole idea, right here
  }
}

    A linked list is a chain of nodes. Each one knows its value and the next node. There is no array underneath — that is the point.

    1. Write a LinkedList with head, a push(value) that walks to the end and links on, and a toArray()
    2. Push four values and print toArray()
    3. Add prepend(value) — put a node at the front. Notice how little work it is
    4. Now write unshift's equivalent on an array of 100,000 items and think about what the computer had to do

    Done when: prepend is three lines and touches two nodes, no matter how long the list is. Adding to the front of an array moves every single element. That difference is the reason linked lists exist.

    Do not skip toArray(). It is how you prove the chain is actually linked, and it is your debugging tool for the rest of the module.

    4 · Map and Set — the two you will actually use

    const seen = new Set([1, 2, 2, 3]);
console.log(seen.size);          // 3 — duplicates are gone

const prices = new Map();
prices.set("rope", 8);
console.log(prices.get("rope")); // 8
    1. Take an array with duplicates and dedupe it in one line with a Set
    2. Build a Map of name → price, then loop it with for (const [k, v] of prices)
    3. Try using an object as a Map key. Then try the same thing with a plain {} and watch it fail
    4. Print prices.size, then work out how you would get the same number from a plain object

    Done when: You can state two things a Map does that an object cannot: any key type, and a real size. Item 3 is the one that surprises people.

    5 · Choosing the shape

    You need to...Reach for
    Look something up by name, constantlyMap
    Know whether you have seen a value beforeSet
    Keep things in order and read them by positionArray
    Always take the most recent thingStack
    Always take the oldest thingQueue
    Insert in the middle over and overLinked list

    Now use it. You have a list of 500 orders and you need to answer "what is order #4471?" a thousand times.

    1. Do it with array.find() — write the line
    2. Do it with a Map keyed by order number — write those lines
    3. Say, in one sentence, what the Map version stopped doing a thousand times

    Done when: Your answer to item 3 mentions searching. find() walks the list every single time; the Map goes straight there.

    Stretch · Make it slow, then measure it

    This is the part that turns Big-O from a definition into something you have seen with your own eyes.

    const N = 100_000;
const arr = Array.from({ length: N }, (_, i) => i);

console.time("shift");
while (arr.length) arr.shift();      // re-indexes every time
console.timeEnd("shift");

    Then build a queue that never shifts — keep a head index and move it forward instead of removing from the front:

    class FastQueue {
  #items = [];
  #head = 0;
  enqueue(v) { this.#items.push(v); }
  dequeue() {
    if (this.#head >= this.#items.length) return undefined;
    return this.#items[this.#head++];    // move the pointer, move nothing else
  }
}
    1. Time 100,000 dequeues from FastQueue the same way
    2. Put the two numbers side by side
    3. Try it again at 10,000 and at 1,000,000, and watch how the gap changes

    Done when: The two times are not close, and the gap grows as N grows. That is the entire content of "O(n²) versus O(n)" — you just measured it instead of being told it.

    Do not memorise Big-O tables. The useful skill is noticing that a loop contains a hidden loop. shift() inside a while is a loop inside a loop, which is why it fell over.
