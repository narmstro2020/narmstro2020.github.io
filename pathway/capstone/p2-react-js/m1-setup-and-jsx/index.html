    7253 Software Development Capstone · P2 React.js · Module 1

    Part 2 · Module 1 — Setup & JSX

    7253 Software Development Capstone · self-guided · work at your own pace

    🎯 Objective

    By the end of this module you can:

    • Scaffold a React project with Vite and say what each generated file is for
    • Read a .jsx file and say which parts are HTML-shaped and which are JavaScript
    • Write a component: a capitalised function that returns JSX
    • Put a JavaScript value into JSX with { }, and know why it is className
    • Explain what Vite does to JSX before a browser ever sees it

    🔑 Why it matters

    Part 2 starts here, and it starts from the app you just shipped. Project 2 is Project 1 rebuilt in React and made bigger. This module builds the shell of that rebuild: a React project that draws your app's page with hard-coded data. No fetch yet, no state yet. Just the page, in JSX.

    Everything you did in Part 1 comes with you. npm create vite@latest is Module 10's command with one word changed. ES modules are Module 8. The functions you write today are Module 2's functions. React is a library, not a new language.

    IdeaWhere you meet it again
    A component is a functionEvery module from here on. Module 2 gives them props
    JSX is JavaScriptModule 5, when .map() builds the list inside the markup
    Vite compiles JSXModule 9, when the build is what gets deployed

    Read Writing Markup with JSX with the three rules in front of you: return a single root, close every tag, camelCase almost everything. Every JSX error you get this week is one of those three.

    The one idea underneath all of it

    JSX is not HTML. It is JavaScript that looks like HTML.

    <h1>{title}</h1> is a function call in disguise. Vite turns it into one before the browser sees it, which is why you can put any JavaScript expression inside the braces, why class has to be className (it is a reserved word in JavaScript), and why a component has to return one thing (a function returns one value). Once that is clear, every JSX rule is a consequence rather than a rule.

    ⌨️ Build — capstone/

    One project, capstone/. Keep it next to your Part 1 app, not inside it. It is the Project 2 repo from today.

    1 · Scaffold it, and read every file

    npm create vite@latest capstone -- --template react
cd capstone
npm install
npm run dev
    1. Open the URL it prints. Click the counter. That is state, and it is Module 3 — ignore it for now
    2. Read index.html. Find the one <div id="root"> and the <script type="module">
    3. Read src/main.jsx. createRoot takes that div; .render(<App />) puts the app inside it. Every React app starts with these five lines
    4. Read src/App.jsx. Find the function, find the return, find the markup inside the return
    5. Look at package.json: react and react-dom are the dependencies; vite and the React plugin are dev dependencies. Say what the difference is

    Done when: You can say what each of the four files does, in one sentence each, and you know why the template says --template react where Module 10 said --template vanilla.

    The dev server hot-reloads. Keep it running in a terminal all module. Save a file, look at the browser. If the browser goes white, the error is in the terminal and in the browser overlay — read it, it names the file and the line.

    2 · Break JSX three ways, on purpose

    In App.jsx, one at a time, then undo each:

    1. Return two sibling elements with no wrapper. Read the error: Adjacent JSX elements must be wrapped
    2. Write <br> without the slash. Read the error
    3. Write class="x" instead of className="x". It runs — now read the warning in the console

    Done when: You have seen all three messages and can say which rule each one is enforcing: one root, every tag closed, camelCase attributes. The fix for the first is a fragment, <>…</>, and you know why it exists.

    3 · Your app's page, in JSX

    Delete everything inside App's return, and the counter code above it. Then rebuild your Part 1 app's page, with hard-coded data:

    1. The header: your app's title and tagline. Put both in consts above the return and use {title} in the markup
    2. Three list items, typed out by hand, showing the same fields your Part 1 list shows. Three, not thirty — .map() is Module 5
    3. At least one value computed in braces: a .toFixed(1), a date formatted with toLocaleTimeString, a string built with a template literal
    4. A {/* comment */} inside the markup explaining why it is className
    5. Copy your Part 1 styles.css over the generated index.css, and delete App.css and the import of it. The class names match, so the page should look like your Part 1 app

    Done when: The browser shows your Part 1 app's page — header, three rows, footer — drawn by React from App.jsx, styled by your own stylesheet, and every piece of text in it came through a { } or a JSX tag you wrote.

    Nothing here fetched anything. That is deliberate. Module 1 is about the shape of a component. When the fetch comes back in Module 6, the markup you wrote today is what it fills.

    4 · Build it, and look at what JSX became

    npm run build
    1. Open dist/assets/. Find the JS file. Search it for your app's title
    2. Notice there is no <h1> anywhere near it — the JSX is gone. Find the function call that replaced it (it will mention jsx or createElement)
    3. Note the size of that file. Most of it is React itself; the number is what Project 2's deploy will ship

    Done when: You have seen, in the built file, that your JSX became function calls. That is the whole answer to “why do I need Vite to run this” and it is the exit ticket.

    Stretch · Write the function call yourself

    1. In App.jsx, add import { createElement } from "react";
    2. Replace one element — the footer's paragraph — with createElement("p", null, "Data from …")
    3. Confirm the page is identical. Then put the JSX back and write two sentences about why nobody writes it the long way

    Done when: You have written one element without JSX and it rendered. JSX is now a convenience you understand rather than syntax you obey.

    ✅ Check Yourself

    Can you, without looking anything up:

    • Name the three JSX rules and the error each one produces when broken?
    • Say why it is className and not class?
    • Say what createRoot(…).render(<App />) does, and where root comes from?
    • Say what a fragment is for?
    • Say what Vite did to App.jsx before the browser got it?
    • Say which two packages are dependencies and which are dev dependencies, and why the split?

    If any box is unchecked, spend twenty minutes on that row's resource. Then check it.

    🏁 Done When

    • capstone/ is a Vite + React project that runs with npm run dev and builds with npm run build
    • App.jsx draws your Part 1 app's page from hard-coded data, styled by your own stylesheet
    • At least one value in the markup is computed inside { }
    • The template's counter, logo, and App.css are gone
