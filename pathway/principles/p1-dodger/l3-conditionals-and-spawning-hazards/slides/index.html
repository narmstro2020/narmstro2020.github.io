Build · Step 1 — stay on screen

One line, at the end of _process().

position.x = clamp(position.x, 32, screen_size.x - 32)

clamp() takes a number and two limits, and gives you back the number squeezed into that range. Below the minimum you get the minimum; above the maximum you get the maximum.

Why 32 and not 0? Because position is the centre of your square, and your square is 64 wide. Try 0 and watch half of it hang off the edge.

Build · Step 2 — Hazard.gd
extends Area2D

@export var fall_speed := 300.0

func _process(delta: float) -> void:
	position.y += fall_speed * delta

	if position.y > get_viewport_rect().size.y + 50:
		queue_free()
fall_speed * delta — the same pattern you wrote yesterday. Every moving thing in every game you make from now on uses it.

queue_free() means
"delete me at the end of this frame."

Forgetting it has a name: a memory leak. You'll watch your own frame rate drop.

Build · Step 3 — spawning from Main
  1. Open Main.tscn, select Main, add a Timer child named SpawnTimer
  2. Inspector: Wait Time 1.0, Autostart ✅
  3. Attach Main.gd and type the script
  4. Drag Hazard.tscn into the Hazard Scene slot in the Inspector
Step 4 is the one everybody forgets. Nothing spawns without it, and the error you get — Invalid call on null instance — does not mention the Inspector at all.
Main. Now with a clock.

One Timer node is the entire spawner.
The script only answers when it fires.

Build · Step 3 — Main.gd
extends Node2D

@export var hazard_scene: PackedScene

func _ready() -> void:
	$SpawnTimer.timeout.connect(_on_spawn_timer_timeout)

func spawn_hazard(pos: Vector2) -> void:
	var hazard := hazard_scene.instantiate()
	hazard.position = pos
	add_child(hazard)

func _on_spawn_timer_timeout() -> void:
	var screen_size := get_viewport_rect().size
	var x := randf_range(32, screen_size.x - 32)
	spawn_hazard(Vector2(x, -50))

Two steps. Both required.

1 · make it
var hazard := hazard_scene.instantiate()

Stamps a copy from the blueprint. It exists in memory now — and it is nowhere on screen.

2 · put it in the game
add_child(hazard)

Adds it to the running scene tree. Now it draws, and now its _process() runs.

Skip add_child() and you get no error and nothing on screen. The object is real; it just isn't in the game.

Nobody is watching the clock.

A signal is one object announcing that something happened. .connect() says "when that happens, run this." No loop is checking. This is how real applications are built.
