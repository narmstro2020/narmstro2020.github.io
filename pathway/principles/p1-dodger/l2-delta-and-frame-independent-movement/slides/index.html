The fix

delta is seconds since the last frame.

Slower computer → bigger delta → bigger step. It compensates automatically.

Multiply by delta and the units change.

speed * delta at 60 fps400 × 0.016 ≈ 6.4 px this frame
speed * delta at 144 fps400 × 0.007 ≈ 2.8 px this frame
Over a whole second400 px. Both.

Small steps taken often, or big steps taken rarely. Same distance.

speed now means pixels per second, which is a number a human can reason about.
400 pixels per frame would be 24,000 pixels per second. Off the screen in three frames.
Why frame rate is a hardware question
CPU
Runs your GDScript. Decides where things go.
GPU
Draws the pixels. Decides how fast a frame appears.
RAM
Holds the scene while it runs.
Storage
Holds the project when it's closed.
Refresh rate
How often the monitor can show a new frame at all.
delta
Your code's only honest reading of all of it.

Build · Step 1

The whole script.

extends Area2D

@export var speed := 400.0

var screen_size: Vector2

func _ready() -> void:
	screen_size = get_viewport_rect().size
	position = Vector2(screen_size.x / 2, screen_size.y - 100)

func _process(delta: float) -> void:
	var direction := 0.0
	if Input.is_action_pressed("ui_right"):
		direction += 1.0
	if Input.is_action_pressed("ui_left"):
		direction -= 1.0

	position.x += direction * speed * delta

The underscore is gone from _delta — we're using it now.

@export puts a variable
in the Inspector.

One word in front of a variable, and the number becomes something you can change while the game is running — no code, no re-save, no hunting.

This is how every game studio tunes a game. The designer never opens the script.

_ready() runs once.
_process() runs every frame.

var screen_size — outside a functionLives as long as the object does. Set once in _ready()
var direction — inside _process()Created and destroyed every single frame
Yesterday
if right:
    position.x += 5

    position.x -= 5
Today
var direction := 0.0
if right: direction += 1.0
if left:  direction -= 1.0

position.x += direction * speed * delta

One variable holding
-1, 0, or 1.

Why is that better? There is now exactly one place that multiplies by speed and delta. Change how movement works and you change one line.

Both keys held at once? direction is 0. You get "stand still" for free, without writing it.
