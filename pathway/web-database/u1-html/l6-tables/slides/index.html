60 seconds. Which one, and why?

A table is for data. Never for layout.

Rows and columns of information — not boxes on a page.

Why the rule exists

People used to build whole pages
out of tables.

CSS couldn't do layout yet, so a 2000s page was tables nested inside tables inside tables. It worked. It was terrible.

A screen readerreads it as a data table and announces nonsense
A phonecan't reflow it — you get a tiny desktop page
You, in a monthcan't find anything in six levels of nesting

Unit 2 gives you CSS, which is the actual answer to layout.

Four tags
<table>the whole thing
<tr>a row — everything in one goes across
<th>a header cell — names what the column (or row) holds
<td>a data cell — one piece of information
<th> means header, not "top row." The first cell of a row can be a <th> too — that's how you label rows as well as columns.
The shape
<table>
  <thead>
    <tr>
      <th>Park</th>
      <th>Hours</th>
      <th>Entry fee</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Turkey Run</td>
      <td>7am – 11pm</td>
      <td>$7</td>
    </tr>
  </tbody>
</table>

A table is a stack of rows. A row is a list of cells. Every cell lives inside a <tr> — never directly in the table.

thead and tbody
change nothing you can see.

Same as <strong> versus <b> back in Lesson 2 — you're labelling meaning, and a machine is the one reading it.

A browser repeats the header row on every page when the table is printed.
A screen reader announces "Hours: 7am to 11pm" instead of just "7am to 11pm" — it reads the header with each cell.

Third time this idea has come up. It'll come up again in Lesson 10.

Break it on purpose

Delete one <td>
from the middle row.

The whole table goes jagged.

Every row needs the same number of cells. When a table looks wrong, count the cells in each row — that's the fix almost every time.

When one cell covers two.

<td colspan="2">Closed for the season</td>

colspan spans across. rowspan spans down.

Only when the data actually says so. A merged cell that doesn't reflect the information is worse than no merge at all.
And remember the counting rule — a colspan="2" cell counts as two. That's why these break tables.
