Is HTML
a programming language?

Think for 60 seconds. Then hands. Be ready to say why.

No. HTML is markup.

No logic. No variables. No loops. You are labelling content, not instructing a machine.

Standard D1.1 · where markup came from
HTML was invented so physicists could share documents — not to build apps. Every weird thing about it makes sense once you know that.
The anatomy of an element

Open it. Fill it. Close it.

Elements nest
like boxes in boxes

  • <html> — the whole document
  • <head> — information about the page. The browser reads it; nobody sees it
  • <body> — the page itself. Everything anyone actually sees
Your <title> goes in the head. It shows up on the browser tab, not on the page.
Today's learning target

I can build an HTML page by hand with a correct
heading outline, and get my own content into a browser.

Students will demonstrate this learning target with at least 80% accuracy on today's checkpoint.

Your page will have no colours, no fonts, no layout. It will look like it's from 1994. That is not a bug. Structure first — styling is all of Unit 2.

Step 1 · 21 minutes

Type the skeleton

  1. VS Code → New File
  2. Save As → index.html, inside your 01_Site folder
  3. Type the skeleton by hand — doctype, html, head, title, body
  4. Put your topic in the <title> and the <h1>
  5. Open it in the browser
Every character by hand. No copy-paste, no Emmet, no AI. You can't debug what you didn't type.
The loop

"My change isn't showing up" is always one of these two steps.

New idea · attributes

Extra information inside a tag. Always name="value".

Headings are an outline,
not font sizes

  • <h1> — the page's one main title. One per page, ever.
  • <h2> — a section of that page
  • Screen readers build their navigation from this. So do search engines.
Use <h1> four times because it "looks bigger" and your page still looks fine. It's still wrong, and nothing will tell you.
Whitespace
collapses.

Ten spaces, one space, five blank lines — the browser renders all of them the same way. One space.

Spacing is CSS's job, not the spacebar's. That's Unit 2.
Step 2 · 19 minutes

Make it yours

  1. Add lang="en" to your <html> tag
  2. Real <title> — your topic, on the tab
  3. One <h1>, then an <h2> for each section
  4. Real paragraphs under each heading
Real sentences. Not aaa, not lorem ipsum. A stranger should be able to read your page and know what it's about.
It's your site. Your topic. All year.

Every lesson from here adds to this same file. In thirteen weeks it's a real website with your name on it.

Step 3 · Break it on purpose · 8 minutes

Delete </body>.

Save. Refresh. What happened?

It still worked. That's the problem.

The browser guessed what you meant and moved on. It will not always guess the way you want.

HTML doesn't crash. It renders weird. Reading "weird" is the whole skill.

If it's not working

The file downloads instead of showingYou saved it as .txt — Save As, and fix the name
Tab says "index.html", not your title<title> is empty, or it's not inside <head>
The whole page is one giant headingMissing </h1>
Your spacing in the code does nothingCorrect. Whitespace collapses — spacing is CSS's job
Your attribute is ignoredMissing quotes, or a typo in the attribute name
Your edits don't appearYou didn't save, or you didn't refresh
Your tags show up as text on the pageA missing < or > somewhere above

Look at the page, then find the tag that caused it. Nothing is going to tell you where to look.

Working with your partner

Finished early?

In VS Code, type ! and press Tab. Watch the whole skeleton appear.
  • That's Emmet, and every professional uses it every day.
  • So why did we spend twenty-five minutes typing it by hand?
  • Because you can't debug what you don't understand. Now that you've typed it, the shortcut is a shortcut. Before that, it was magic.

Or add a title attribute to a paragraph and hover over it. Attributes change behaviour, not just information.
