The shape of a form

Four parts, every time

<form action="#" method="post">

  <label for="name">Your name</label>
  <input type="text" id="name" name="name">

  <button type="submit">Send it</button>

</form>

action is where it goes. method is how it travels.
Both get explained properly in Unit 6 — they are literally standard D1.14.

for = id

<label for="email">Email</label>
<input type="text" id="email" name="email">
Those two strings must match exactly.
That is the entire mechanism.

Test it without reading a line of code.

Click the label text.
If the cursor jumps into the box, they match. If nothing happens, they do not.

Two seconds, and it works on every form you will ever write.

Why it matters, concretely

A label is not decoration

Without a paired labelWith one
A screen reader announces "edit text, blank"It announces "Email, edit text"
The user has to guess what the box wantsThey are told
The clickable target is the box onlyThe label is clickable too — easier with a tremor or on a phone
A placeholder is not a label. It disappears the moment you start typing.

A contact page

  1. Make contact.html, and copy your <header> and <nav> into it — then add it to the nav on every other page
  2. A text field for a name, and a field for an email
  3. A <textarea> for a longer message
  4. A <select> dropdown that fits your topic
  5. A submit button

Every single input gets a paired <label>. No exceptions.

The dropdown

<select>

<label for="park">Which park?</label>
<select id="park" name="park">
  <option value="">-- pick one --</option>
  <option value="shades">Shades</option>
  <option value="brown-county">Brown County</option>
</select>

The value is what gets sent. The text between the tags is what the user sees. They do not have to match.
