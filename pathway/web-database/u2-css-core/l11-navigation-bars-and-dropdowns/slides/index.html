A nav that is a bar.

Blocks, not words. The page you are on. A menu that drops down — for the mouse and the keyboard.

A nav bar is five things you already own
a barbackground, no bullets, items in a row — L6, L7, L8. Done
links as blocksdisplay: block and padding on the a, so the whole box is the link — L7
the page you are ona class on that page's item — L1
a menu that drops downhidden, position: absolute under its item — L7, L8
shown on hover and keyboard:hover, :focus-within — L6, L10
Step 1 — blocks, and the current page
nav {                                   /* a SECOND nav block: later wins */
  padding: 0 1rem;
  li { margin-right: 0; padding: 0; position: relative; }
  a  { display: block; padding: .75rem 1rem; }
  .current > a { background-color: var(--accent); }
}

In the HTML, put class="current" on each page's own item. Four pages, four different items.

position: relative on the li changes nothing you can see. It is the box the menu will measure from. You know this one.

Step 2 — the markup, every page
<li class="has-menu">
  <a href="turkey-run.html"><span class="fa-solid fa-tree" aria-hidden="true"></span> Turkey Run</a>
  <ul class="menu">
    <li><a href="turkey-run.html#route">Rocky Hollow, in order</a></li>
    <li><a href="turkey-run.html#trails">Trails by difficulty</a></li>
    <li><a href="turkey-run.html#glossary">Words the signs use</a></li>
    <li class="soon">Shades &mdash; coming soon</li>
  </ul>
</li>

The item's own link still works. A phone cannot hover, and it loses nothing.

Step 3 — the menu
nav {
  .menu {
    display: none;
    position: absolute; top: 100%; left: 0;     /* hangs below its item */
    min-width: 14rem; margin: 0; padding: .25rem 0;
    background-color: rgba(20, 83, 45, 0.95);
    li { display: block; }                       /* stacked again */
    a  { text-transform: none; letter-spacing: 0; font-weight: 400; padding: .5rem 1rem; }
  }

  .has-menu:hover .menu,
  .has-menu:focus-within .menu { display: block; }
}
Opacity
.soon {
  opacity: .55;
}

Fades the whole element: text, border, everything in it.

.menu {
  background-color: rgba(20, 83, 45, 0.95);
}

Fades one colour. The text on it stays solid.

Text at opacity: .55 is hard to read. It is right for “not yet,” and wrong for anything someone has to read.

The test

Put the mouse down.
Tab through it.

Delete the :focus-within line and Tab again. The menu never opens, and its three links do not exist to the keyboard — display: none cannot take focus. Put it back.

Before you leave

  • Links are blocks; the page you are on is marked, on all four pages
  • The menu drops down on hover and on Tab, with a small arrow on its item
  • One thing faded with opacity, one with rgba, and you can say the difference
  • Still zero validator errors. Back up as Site_U2L11_LastnameF

Exit ticket: the menu opens on :hover. Why is :focus-within in the same rule, and what happens to a keyboard user without it?
