Errors move from runtime to compile time. That's the trade.

Where do you want
to find the mistake?

  • Interpreter: an error on line 400 surfaces when line 400 runs — possibly in front of a user
  • Compiler: it reads all of it first and refuses to produce anything until it makes sense
This is going to annoy you for about two weeks, and then you're going to love it.
The third one · D1.2

A code generator is a program
that writes source code for you.

You've already met one. VS Code's Source Action → "generate getters and setters" — you'll live in it in Unit 2.

Compiler, interpreter, code generator. That's the whole family.

Java is both.

javac compiles to bytecode — not machine code. The JVM then runs that.

That's what "write once, run anywhere" actually means.

Today's learning target

I can describe how source code becomes a running program,
and get my own Java project to compile and run.

Students will demonstrate this learning target with at least 80% accuracy on today's checkpoint.

Today's output is four lines of text in a console. No window, no graphics. Sixty percent of professional software has no graphics at all — and this project becomes your Project 1 game in a few weeks.

Step 1 · 15 minutes

Start the project

  1. Ctrl+Shift+P → Java: Create Java Project
  2. Choose No build tools, pick your folder, name it ArenaGame
  3. In src, new file Main.java
  4. Type the class and main method by hand
  5. F5 to run — or click Run above main
Red squiggles everywhere on a brand-new project means the Java extension can't find a JDK: Ctrl+Shift+P → Java: Configure Java Runtime.

It compiled.

And it still didn't run.

The compiler checks grammar, not meaning.

A sentence can be perfectly formed and still say nothing the machine can use. "It compiles" is not the same as "it works."
