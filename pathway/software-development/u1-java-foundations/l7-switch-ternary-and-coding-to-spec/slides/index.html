Both.

Without break, execution falls through into the next case. It compiles. It runs. It's wrong.

One arrow. Bug gone.

switch (action) {
    case "A" -> System.out.println("You attack.");
    case "D" -> System.out.println("You defend.");
}
Arrow cases don't fall through. You'll never write break in this course — the bug can't happen.

Two kinds of switch

It does things

switch (action) {
    case "A" -> { ... }
    default  -> { ... }
}

No semicolon.

It is a value

String name = switch (n) {
    case 1 -> "Easy";
    default -> "Unknown";
};

Semicolon — it's one statement.

Try this

Delete the default
from the expression switch.

It won't compile.

An expression has to produce a value every time, and Java can't prove that without a default.
Compare that to Lesson 3. Integer division silently gave you 0% and said nothing. Same language, two very different philosophies.
The ternary
potions == 1 ? "potion" : "potions"

Read it as a question: "is potions equal to 1? If yes, give me "potion". If no, give me "potions"."

System.out.printf("You have %d %s left.%n",
                  potions, potions == 1 ? "potion" : "potions");
A ternary chooses a VALUE. Writing this as an if takes four lines to pick one word.
Where the ternary goes wrong
potions == 1 ? "potion" : "potions"Choosing a value — correct
ok ? doThis() : doThat();Choosing an action — that's an if
a ? b : c ? d : eNested. Legal, and unreadable
Choosing a value → ternary. Choosing an action → if. That rule holds up everywhere.
