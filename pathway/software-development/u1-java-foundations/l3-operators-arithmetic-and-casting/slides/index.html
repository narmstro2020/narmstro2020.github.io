What does Java print?

int a = 7 / 2;
System.out.println(a);

60 seconds. Write your answer down before you say it.

3

Not 3.5. Not rounded to 4.

And no warning. The compiler is completely happy. This is not an error — it is Java doing exactly what you asked.

int ÷ int is always an int.

The fraction is truncated, not rounded. 9 / 10 is 0. Remember that one — it's where percentages die.

Four lines. Read line 2 twice.
int    a = 7 / 2;            // 3   — no surprise now
double b = 7 / 2;            // 3.0 — the damage was already done
double c = 7.0 / 2;          // 3.5
double d = (double) 7 / 2;   // 3.5
Line 2 is the one that catches people. Java did the whole calculation as ints, got 3, and only then widened it to 3.0.

The type on the left never reaches backwards into the math on the right.

Two ways to fix it
cast
(double) hits / swings
Force one side to be a decimal.
reorder
hits * 100.0 / swings
Get a decimal into the math early.
both
Same answer. Neither one is "more correct."

One side has to be a double before the division happens.

Casting truncates.
It does not round.

(int) 3.9    // 3
(int) 3.999  // 3
(int) -3.9   // -3

It chops toward zero and throws the rest away — the same behaviour as integer division, which is not a coincidence.

Want actual rounding? Math.round(3.9) gives 4.
Casting the wrong way loses data silently. Going double → int always costs you something. Java makes you write the cast so you can't do it by accident.
