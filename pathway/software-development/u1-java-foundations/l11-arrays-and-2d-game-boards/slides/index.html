How many variables would ten take?

Arrays fix that.

String[] inventory = new String[5];      // fixed size, all null
int[] damageLog = new int[10];           // all 0
String[] names = {"Potion", "Key", "Rope"};   // size inferred
Three facts that cause every array bug

Learn these before you type

  1. Fixed size at creation. new String[5] is five forever. (ArrayList in Unit 2 fixes this.)
  2. .length is a field, not a method — no parentheses. Unlike String.length().
  3. Indices run 0 to length - 1. An array of 5 has no index 5.
Fact 2 is genuinely inconsistent and it catches everyone. array.length — string.length().

Build · Step 2 — 25 minutes

The arena becomes a real board

char[][] arena = new char[5][11];

for (int r = 0; r < arena.length; r++) {
    for (int c = 0; c < arena[r].length; c++) {
        boolean edge = (r == 0 || r == arena.length - 1
                     || c == 0 || c == arena[r].length - 1);
        arena[r][c] = edge ? '#' : ' ';
    }
}
arena[playerRow][playerCol] = '@';

And drawing it is now three lines

Enhanced for, earning its place

static void drawArena(char[][] arena) {
    for (char[] row : arena) {
        System.out.println(new String(row));
    }
}

A 2D array is an array of rows. Each row is itself an array.

Movement is now three steps.

  1. Clear the old cell — arena[r][c] = ' ';
  2. Update the position
  3. Set the new cell — arena[r][c] = '@';
Collision is just checking what is already in the target cell.
That is exactly what Unit 3 does with sprites.

Break it on purpose — twice

Two errors, two causes

→ ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5

→ NullPointerException
Read them aloud. Java's array messages are unusually good — the first one tells you the index and the length.
